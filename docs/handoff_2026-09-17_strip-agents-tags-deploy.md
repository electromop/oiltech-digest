## Ревью: фича тегов была пустышкой ИМЕННО на проде

Самая дорогая находка сессии, и она про мою же работу.

`_tags_scope()` читал тематики из базы. Но `AI_EXECUTION_REGION=external` — гейт
исполняется на воркере в Амстердаме, **у которого базы нет**
(`docker-compose.external-worker.yml` без `DATABASE_URL`). Чтение падало в `except`,
блок молча уезжал пустым. При этом теги **уже лежали в payload** воркера для соседней
стадии тегирования — их надо было просто передать.

**Правило на будущее:** если стадия может уехать на stateless-воркер, данные ей
передаются параметром, а не читаются из базы. Локальные тесты этого не ловят никогда —
там база есть.

Того же класса вторая находка: `tags_scope_block` склеивал русские и английские ключи
и резал общим срезом. Русских в справочнике 33–52 на тематику, поэтому **английские не
доезжали до модели ни разу** — при том что гейт судит англоязычные тексты, и это ровно
те издания, ради которых включали зарубежный контур. Проверено прогоном, не
рассуждением. Квота теперь на каждый язык отдельно.

Третья: служебный приёмник «Не классифицировано» уходил в блок как тематика заказчика,
то есть по правилу 2б становился доводом ЗА для всего непонятого.

## Деплой упал, сайт лежал около десяти минут

`bootstrap` падал с `DeadlockDetected` на `relation 16440`. Это **`background_jobs`**.
Бутстрап берёт на неё `AccessExclusiveLock` для ALTER, а контейнер `oiltech_tasks`
обслуживает внешний воркер и непрерывно пишет в ту же таблицу → `RowExclusiveLock`.

**`schema.sql` этим выкатом НЕ менялся** — проверено диффом. Дело не в схеме.

Рабочая последовательность:

```bash
docker compose stop tasks
docker compose run --rm bootstrap
docker compose up -d
```

Ложный ход: сначала решил, что это гонка трёх копий бутстрапа (`up app scheduler worker`
тянет зависимость трижды). Повтор в одиночку дал тот же дедлок — версия неверна.

# Дополнение вечера 17.09: обрывки, Energy Voice, перепечатки

## Обрывки (пункт 25) — механизм построен, упирается в воркер

Причина была двойная и обе половины закрыты в коде:

1. Зарубежный сбор по RSS брал **только анонс ленты** и страницу статьи не качал
   никогда. Замер: у Oil & Gas Journal и Offshore Magazine 25 из 25 статей короче
   600 знаков, средняя длина 183; McKinsey 76 из 78; Upstream Online 173 из 187.
2. Локальная дозагрузка на этих источниках ловит 403 гарантированно, а попытка
   там **одна и навсегда** — статья получала `failed` и больше не переспрашивалась.

Сделано: внешний RSS добирает тело на воркере; локальная дозагрузка источники
`network_region='external'` пропускает; добавлена задача `refetch_text` для
дозаполнения уже лежащих обрывков со стражем принадлежности (№24) на приёме.

Проверено вручную: статья, лежащая в базе как 231 знак, с западного адреса
извлекается в **2297 знаков**.

## Energy Voice (пункт 15) — не чинится с нашей стороны

За **Cloudflare «Just a moment»** — JS-челлендж. 403 и с западного адреса, и по

## Перепечатки (пункт 21) — правило ловит, модель решает

Замер на подлинном случае заказчика от 08.09 («все 4 новости об одном») показал,
почему единого порога не существует: совпадение значимых слов между настоящими
дублями — от 36% до 78%, по телу 23–42%. Дедуп по заголовку поймал бы две копии
из четырёх.

Правило (разные источники, ≤5 дней, пересечение ≥35%) сужает 30 000 статей до
**~16 пар в сутки** (замер: 221 пара за 14 дней). Выборка из «слабой» полосы
36–55%, где ожидался шум, дала **6 настоящих дублей из 6** — полоса не мусорная.

Модель отвечает на узкий вопрос «одно ли это СОБЫТИЕ» и выбирает главную копию.
Помечаем в отдельной обратимой таблице `article_reprints`, не удаляем.

## Две ловушки выката, на которые я наступил

**`docker compose build app scheduler worker` не пересобирает `bootstrap`,** а
схему применяет именно он. Таблица `article_reprints` молча не создалась, при этом
бутстрап отчитался об успехе. Проверка: `grep -c <новое> /app/.../schema.sql`
внутри образа бутстрапа.

**`docker compose up -d` дёргает `bootstrap` как зависимость** и роняет запуск
сервисов. Рабочая последовательность:

```bash
docker compose stop tasks worker scheduler
docker compose build app scheduler worker bootstrap
docker compose run --rm bootstrap
docker compose up -d --no-deps app scheduler worker tasks
```
