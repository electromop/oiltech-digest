# Бот «Материалы коллег» — запуск и выкат

Рабочая группа в Telegram, куда сотрудники в одном формате вносят материалы, полезные
нефтесервисным обществам, с упором на бизнес: ссылка с описанием, файл с описанием или событие
своими словами. Каждый материал идёт с оценкой автора по шкале платформы (те же девять пунктов,
что у карточки радара). Материалы видны на экране «Материалы коллег», по ним ориентируются
аналитики. Следующий шаг: карточка сигнала, когда материал проходит порог релевантности (`signal_id`).

## Как это выглядит для сотрудника

```
/add
 → [🔗 Ссылка + описание] [📎 Файл + описание] [📰 Событие] [✖ Отмена]
 → ссылка / файл (до 20 МБ; подпись к файлу становится заголовком)
 → заголовок одной строкой
 → описание: что произошло, кто участники, чем важно (от 20 символов)
 → компании через запятую («-» — пропустить)
 → оценка: 9 кнопок шкалы платформы
 → комментарий к оценке («-» — пропустить)
 → карточка на проверку: [✅ Отправить] [↺ Заново] [✖ Отмена]
 → в группе остаётся только «Материал №N принят на платформу»: вопросы бота, /add и ответы
   автора стёрты; у файла остаётся и сообщение с файлом; материал из лички уходит и в группу
```

Команды: `/add`, `/history` (история и статус своих материалов, по 10, кнопка «Ещё»; прежняя
`/my` работает так же), `/cancel`, `/help` (формат и шкала). В группе ответ на `/history` и
сама команда стираются через 2 минуты.

- **У каждого свой цикл.** Диалог ведётся по паре «чат × человек».
- **Ответы в группе.** Там бот задаёт вопрос с ForceReply, адресованным автору, а ход диалога
  двигает только ответ на свой вопрос.
- **Чужие кнопки.** На нажатие кнопки другого участника бот отвечает «Это меню другого участника».
- **Брошенный ввод** забывается через 30 минут.
- **Повтор без дублей.** Повтор «Отправить» после сбоя связи материал не двоит.
- **Сбой Telegram.** Если Telegram не принял вопрос бота, шаг не сдвигается: тот же ответ,
  отправленный ещё раз, ведёт дальше. Любая ошибка обработки не роняет бота: автор получает ответ.
- **Личка.** В личке бот работает только с участниками рабочей группы.

## Настройка (владелец, один раз)

1. **@BotFather**: `/newbot`. Имя — «OilTech · Материалы коллег», username — например
   `oiltech_materials_bot`. Токен кладётся в `.env.external-worker` на NL, в чат его не выводить.
   - Режим приватности (`/setprivacy`) можно оставить **включённым**: бот получает команды и
     ответы на свои сообщения, этого достаточно.
   - `/setjoingroups`: после добавления в группу — Disable, чтобы бота не утащили в чужие чаты.
   - Аватар — `/setuserpic`.
   - Описание, короткое описание и меню команд бот ставит себе сам при старте
     (`tg_materials_bot.DESCRIPTION`, `SHORT_DESCRIPTION`, `COMMANDS`).
2. **Группа**: создать «OilTech · Материалы коллег», добавить бота и **сделать администратором**
   с правом удалять сообщения. Без этого права бот не сможет стирать свои промежуточные вопросы.
3. **ID группы**: переслать любое сообщение группы боту `@getidsbot` (или посмотреть в
   `getUpdates`). Вид — `-100…`.
4. **`.env.external-worker` на NL**:
   ```
   TG_MATERIALS_BOT_TOKEN=<токен>
   TG_MATERIALS_CHAT_IDS=-100…
   ```
   `CORE_API_URL` и `EXTERNAL_WORKER_TOKEN` там уже есть, бот берёт их же.

### Описание группы (поле «Описание»)

> Материалы для нефтесервиса: сделки, контракты, рынок, заказчики, конкуренты, регулирование.
> Вносите через бота — /add. Каждый материал попадает на платформу OilTech с вашей оценкой.

### Закреплённое сообщение

> 📌 **Как вносить материалы**
>
> Команда **/add**, дальше бот проведёт по шагам: тип (🔗 ссылка · 📎 файл · 📰 событие) →
> заголовок → описание → компании → ваша оценка по шкале платформы → карточка на проверку.
>
> Отвечайте боту **ответом (reply)** на его вопрос: так он не спутает ваши ответы с чужими.
> Удобнее — в личке бота, там можно писать без reply.
>
> Что полезно: контракты и тендеры, сделки M&A, выход и уход игроков, цены и загрузка флота,
> изменения у заказчиков, регулирование и налоги, кадровые новости, отчётность.
>
> /help — формат и шкала · /history — мои материалы и их статус · /cancel — отменить ввод

## Выкат

Порядок как всегда: сначала ядро (оно понимает и старый NL), потом NL. Номер контракта не
меняется: добавка совместима, старые воркеры новых эндпоинтов не зовут.

1. **РФ, ядро.** Новая таблица `colleague_materials`. Её можно создать заранее точечно и выкатить
   без init-db:
   ```bash
   docker exec -i oiltech_pg psql -U oiltech -d oiltech_digest < scripts/materials/materials-before-deploy.sql
   sh scripts/deploy-core.sh --no-schema app
   ```
   Либо `--schema`, если выкат с init-db приемлем (в `schema.sql` есть массовые UPDATE, см. CLAUDE.md).
2. **NL** (владелец): после правки `.env.external-worker`:
   ```bash
   sh scripts/deploy-nl.sh tg-materials-bot
   ```
   Остальных воркеров бот не трогает, поэтому выкатывать его можно и во время радара. Выкат
   ждёт, что контейнер отметится в ядре: бот шлёт `materials/hello` при старте и раз в 5 минут.
3. **Проверка**: в группе `/help`, затем `/add` → «📰 Событие» → пройти шаги → «Отправить».
   Материал должен появиться на экране «Материалы коллег».
   В логах: `docker compose -f docker-compose.external-worker.yml logs --tail 50 tg-materials-bot`
   — строка `tg_materials_bot_started username=…`.

Без токена или списка групп бот не падает, а пишет в лог `tg_materials_bot_disabled` и только
отмечается в ядре. Так выкат NL по умолчанию (все сервисы) не встаёт, пока бот не настроен.

Память NL (1,9 ГБ): контейнер бота — один процесс Python без Chromium, примерно 60–80 МБ.
Перед первым `up` проверить `free -m`.

## Дальше (не сделано)

- **Порог → карточка сигнала.** Судья радара на NL оценивает материал (тема, бизнес/технология,
  балл), и при прохождении порога появляется карточка в бизнес-ленте, связанная через `signal_id`.
- **Оценка автора → обучение.** Пишется в `signal_feedback_events` после того, как появится
  карточка. Сейчас вердикт хранится только у материала: без сигнала учить судью не на чем.
- **Файл → разбор документа.** Тот же разбор, что на экране «Материалы» (`process_document`).
