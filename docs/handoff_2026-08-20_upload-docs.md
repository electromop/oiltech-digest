## Что доказано, а не заявлено

### Новостной скоринг к документу неприменим — арифметика

Считано по коду (`pipeline.py`, `prompts.py`, `config.py`), не по ощущению.

**Асимметрия входа.** Модель видит `_compact(raw_text, 6000)` — первые ~5% 60-страничного
документа. А keyword-половина балла считается по `_search_text(article)` (`pipeline.py:541`),
где `raw_text` берётся **целиком, без обрезки**. Две части одного балла смотрят на разные
объёмы текста.

**Насыщение keyword.** `keyword_score_for_criterion` — счёт присутствия, не плотности:

```
критерий с  5 ключевыми словами: 3 совпадения где угодно в тексте → 100
критерий с 20 ключевыми словами: 5 совпадений                     → 100
критерий с 40 ключевыми словами: 7 совпадений                     → 100
```

**Завышение.** `final_score = max(ai_score, 0.2·kw + 0.8·ai)`. При `kw = 100` это пол:

```
ai=30 → 44     ai=50 → 60  ← ровно порог дайджеста
ai=40 → 52     ai=60 → 68
```

Модель прочитала первые 5% отчёта, сочла посредственным (50) — документ выходит с 60.
Не по содержанию, а **по длине**. Тот же класс дефекта, что инцидент 06.2026 с блендингом,
только с обратным знаком: там формула топила балл, здесь надувает.

**Семантика.** `SUMMARY_INSTRUCTIONS`: «Отрази, **что произошло**». `SCORING_INSTRUCTIONS`:
якоря 85–100 = «промышленное внедрение, измеримый эффект», плюс абзац, различающий
«статья описывает ПРОБЛЕМУ, а не улучшение». Обзор рынка не является ни событием, ни
проблемой, ни улучшением — режима для такого входа у промпта нет.

**Отсюда три обязательных отличия скоринга документа** (Р2+Р3): вход — свёртка документа,
а не первые 6000 знаков; keyword-блендинг выключен (`final = ai_score`); якоря переписаны
под «применимое знание» вместо «событие». Список критериев из `scoring_criteria` при этом
остаётся тот же — меняются вход, формула и якоря.

## Периметр (инженерные умолчания, приняты без отдельного вопроса)

- **Тип файла** — по сигнатуре, не по расширению и не по `Content-Type`.
- **Имя** — хранить под сгенерированным идентификатором; пользовательское имя не превращать в путь.
- **Лимит на файл** — 25 МБ (60-страничный PDF = 2–5 МБ; презентация с картинками до 20 МБ).
  Квота на пользователя и на систему — иначе пакетная загрузка из Р6 упирается в диск молча.
- **docx/pptx = zip** — ограничить суммарный распакованный размер, число элементов, отношение
  сжатия. Отдельно: внутренности OOXML — это XML, внешние сущности и DTD в парсере выключить явно.
- **Сканы** — отклонять с честным сообщением, OCR в v1 нет. Проверка по объёму извлечённого
  текста на страницу: у скана текстового слоя нет, парсер вернёт пустоту, а модель уверенно
  сочинит сводку из ничего. Это тот же класс дефекта, против которого стоит «страж
  принадлежности текста».
- **Где парсить** — в воркере, с таймаутом и потолком памяти, файл читается с диска.
  Не в `app`: разбор 60 страниц — пиковая память, а `app` держит веб-сессии на сервере,
  где свободно ~1 ГБ и задокументирован OOM (№10).
- **Том — общий с первой строки.** Урок 03.08: правки брендинга не доходили до выгрузки,
  потому что `app` писал в свою копию, а воркеры читали свою. Загруженные файлы — то же
  самое состояние: пишет `app`, читает воркер.

## Глоссарий (кандидат в `CONTEXT.md`)

Файлов `CONTEXT.md` и `docs/adr/` в репозитории нет; по границе сессии не создавались.

- **Документ** — файл, загруженный пользователем под его аттестацией. Не статья: нет URL,
  нет источника, нет даты публикации в ленте.
- **Карточка документа** — результат разбора документа. Зеркало `article_cards`.
- **Факт** — извлечённая величина: значение, единица, контекст, номер страницы, признак
  подтверждения. Неподтверждённый факт существует, но в бенчи не идёт.
- **Аттестация** — подтверждение загружающего, что он вправе загрузить этот материал.
  Штампуется на каждую загрузку.
- **Публикация** — явное действие, переводящее личный документ в общий корпус. Вторая
  аттестация: «имею право показать команде».
- **Корпус материалов** — множество опубликованных документов; основание для группировки и бенчей.
- **Направление** — тег из дерева `tags`. У документа их несколько, с долей покрытия, одно основное.
- **Компания** — запись справочника с алиасами. Строка из документа привязывается к записи.
- **Балл документа** — оценка по своей шкале. Со скорингом статьи не сопоставим.

## Кандидаты в ADR

1. **Документы — отдельная сущность, а не синтетический источник в `articles`.**
   Трудно обратить (миграция + весь путь обработки), удивительно без контекста
   («почему не переиспользовали ленту?»), реальный размен: недели против дней до демо.
2. **Ответственность за класс данных — на пользователе; путь загрузки идёт через внешний контур.**
   Трудно обратить (это позиция по безопасности, а не код), удивительно (записка к ИБ
   утверждает обратное), реальный размен: скорость против пересогласования с ИБ.
3. **Своя шкала балла для документов.** Удивительно («почему две шкалы?»), реальный размен:
   единообразие интерфейса против осмысленности числа.

## Что вскрыло адверсариальное ревью спеки

Пять независимых рецензентов по осям: соответствие решениям, покрытие открытых вопросов,

1. **Частичные результаты нельзя сохранять через отчёт о прогрессе.** Я написал в спеке,
   что можно. Отчёт о прогрессе несёт одно число; результат внешней задачи попадает в базу
   ровно один раз — при терминальном завершении. Нужно собственное хранилище частичных
   результатов, прецедента на внешнем пути в проекте нет. Нашли независимо четыре
   рецензента из пяти.
2. **Утечка была закрыта только в одну сторону.** Я запретил класть содержимое в исходящую
   нагрузку задачи, но сохранённый результат отдаётся клиенту тем же кодом, а администратор
   видит задачи любого пользователя. Конверт воркера несёт вывод модели — для документа это
   карточка, факты и цитаты. **Разведка эту половину не покрывала**: её ловушка про утечку
   говорит только про нагрузку, не про результат.
