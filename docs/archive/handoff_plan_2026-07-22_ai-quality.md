## 2) Промпты «инцидент релевантен, но не приоритет» (коммит 61bbfa2)

**Архитектурный ответ** (брейншторм 4 линзы + состязательная сверка, проверено кодом): гейт=членство, скоринг=ранг, НЕ замещают — но гейт протекал оценкой степени («НАПРЯМУЮ влияющие на цены»), на инцидентах ломалось (два правила без старшинства → «монетка»). Детали — память `oiltech-gate-scoring-design-0722`.

Правки `prompts.py`:
- **RELEVANCE**: убран язык степени; тайбрейкер «нефтегазовый объект перевешивает причину» (прямое поражение танкера/НПЗ/терминала/транзита → true, перевешивает «удары/обстрелы»; сужение: НЕ любое судно у Ормуза, НЕ актив компании вне производства).
- **SCORING**: «инцидент = фон, не приоритет»; Бизнес-эффект = РЕШЕНИЕ, а не масштаб ЧП. **Load-bearing факт**: `total_score`/`score_label` считает КОД (pipeline.py:456), LLM-значения игнорируются — писать в промпт про них бесполезно.
- **SUMMARY**: у впущенного инцидента называть нефтяной эффект.
- **TAGGING**: убран мёртвый язык «дочерний тег» (таксономия плоская: 18 корневых).

**Активация**: промпты исполняются на NL-воркере (`AI_EXECUTION_REGION=external`) — владелец задеплоил (git pull + `docker compose -f docker-compose.external-worker.yml up -d --build`). Env гейта проверен: relevance на gpt-5.5 ✓.

## 3) Пилот (dry-run recheck, 100 статей на новом гейте)

Вердикты «на удаление» — точно в цель, тайбрейкер работает и проговаривается:
- «США удары по Ирану — прямого поражения нефтегазовых объектов НЕТ» → срез ✓
- Атом (ЗАЭС/Росатом), теплосети, ESG/благотворительность, студенческие олимпиады → срез ✓
- **Ни одного ложного среза нефтяного контента**; танкерные атаки сохранены.
Базлайн: атаки на танкеры уже relevant+низкий score (3.9–24.7); утечки типа `328869` (чистая война relevant=true) новый гейт корректно отклоняет.

## 4) Полная перепроверка (запущена в конце сессии)

**Механизм** (проверен в коде перед запуском): `enqueue-recheck --mark` → воркер ре-гейтит каждую статью новым gpt-5.5 → нерелевантное `mark_article_for_deletion` (pending_deletion) → **скрывается из ленты** (фильтр `WHERE c.relevant IS NOT FALSE AND NOT a.pending_deletion`, repository.py:1357), **НЕ удаляется**, обратимо `recheck-unmark`. `--mark` на проде читается из `job_payload` (api.py:1018, фикс T3 на месте) → `apply_recheck_result` использует mark, не delete (external_ai.py:230).
- Вся база ~14031 статья, ~141 батч по 100, **≈$150** gpt-5.5, **~10–12 ч** фоновой работы.
- Без `--force` → статьи сохранённых дайджестов защищены.
- Просмотр помеченного: `recheck-marked`; удаление (ОТДЕЛЬНОЕ решение): `recheck-purge --yes`; откат: `recheck-unmark`.
- **Ранее в сессии** такой запуск был ОТМЕНЁН по просьбе владельца (141 джоба → cancelled, 0 потрачено) — сначала сделали источники/дайджест.
