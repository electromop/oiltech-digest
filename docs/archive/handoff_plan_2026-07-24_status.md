### Как померить реальный прогресс внешней задачи

Поле `progress` бесполезно: `external_worker.py:139` выставляет **статические 20%** при старте
и больше не трогает. Настоящий счётчик — **heartbeat: он шлётся ровно один раз перед каждой
статьёй** (`external_ai.py:59`), троттлинга в `_safe_heartbeat` нет. Значит число heartbeat
в логах = число обработанных статей:

```bash
ssh root@109.68.213.12 'for w in 10 20 30 40; do echo -n "за ${w} мин: "; docker logs --since ${w}m oiltech_app 2>&1 | grep -c "jobs/1181/heartbeat"; done'
```

⚠️ Окно шире времени жизни текущей попытки захватит heartbeat **прошлых** попыток
(у 1181 их было 3) — считать только от `started_at`.

**Пока `1181` в статусе `running` — НЕ ДЕПЛОИТЬ.** Это не перестраховка: именно деплои
во время активной AI-работы стали причиной инцидента 24.07 (см. `memory/oiltech-lease-loss-incident-0724.md`).
Каждый `docker compose down` уводит core в офлайн на ~40 с → воркер теряет lease → батч в мусор.

Как `1181` завершится (`status='ok'`) — выкатывать накопленное (см. следующий раздел).

## ⚠️ Ловушки, на которых я споткнулся (не повторять)

   в момент `complete`, а не по ходу. Я дважды сделал из пустой таблицы вывод «воркер умер» —
   в первый раз он в этот момент жёг деньги, во второй нормально работал.
   **Проверять heartbeat и логи воркера, а не следы в БД.**
2. **Вердикты сверять поимённо.** Брать `article_id` из `result_json` задачи и сверять с
   `article_cards.relevant`. Агрегат «сколько всего нерелевантных» маскируется притоком новых статей.
3. **Возобновлять массовые прогоны ТОЛЬКО разностью множеств.** `all_article_ids()` отдаёт id
   НЕ по возрастанию — ватермарк по `max(id)` молча пропустил бы 8000 статей.
4. **719 «сигналов без сути» — это не «полезное, ждущее обработки».** 709 помечены релевантными
   СТАРЫМ гейтом; новый отклоняет ~84% (замер: 42 из 50). Их обработка **вычищает** ленту, а не наполняет.

(`api.py:997`). Пока воркер занят длинной задачей, задачи с протухшим lease висят в статусе
`running` и никем не разбираются. Сейчас так висят **1182 и 1184** (lease истёк в 11:07 и 11:14).

умрёт насовсем, задачи останутся `running` навсегда и интерфейс будет врать.
