# Качество радара и «режим ChatGPT» — ветка `fix/radar-quality-viktor` (01.10)

Описание PR и хендофф одним файлом. Выкат — `scripts/radar/radar-quality-runbook.md`.

## Зачем

Замечания Виктора 29.09:
- 75% карточек — бизнес-сигналы;
- оценки завышены;
- в одной карточке разные темы;
- теги не по теме;
- старые сигналы;
- «ChatGPT за сентябрь выдал топ-базу из 20».

Замер прода 29.09: из 84 видимых карточек 6 в шортлисте, ни одной с баллом 80+; у 69 из 82
ссылок нет даты.

## Что сделано

**Судья — в том же вызове** (`signal_discovery._judge_schema`):
- категория: технология / бизнес / другое;
- дата самого события;
- флаг «ссылки о разных событиях» с причиной;
- тема — одна из 13 тематик перечислением (код проверяет; запасной путь — ключи);
- баллы по пяти критериям профиля tech_radar — итог считает `normalize_score_payload`, как у
  статей (ADR 0002, Б3).

**Экран не показывает, но хранит** (`_RADAR_VISIBLE_SQL`):
- бизнес и «другое»;
- смешанные события;
- событие старше 180 дней (`SIGNAL_RADAR_MAX_EVENT_AGE_DAYS`);
- архив (`archive-signals` / `unarchive-signals`, сухой прогон по умолчанию).

Тему рынка радар не ищет (`SIGNAL_RADAR_EXCLUDED_TOPICS`).

**«Режим ChatGPT»** (`signal_research.py`, `SIGNAL_SEARCH_MODE=openai_web`):
- на тему один вызов `gpt-5` со встроенным поиском OpenAI — события за 30 дней с
  первоисточниками; дальше докачка страницы и наш судья, ревью, дедуп;
- ссылка подтверждена, если страница открылась или адрес среди источников, которые вернул поиск
  (`web_search_call.action.sources`); иначе отбрасывается;
- повтор при пустом ответе и сбое, пауза между попытками, признак продвижения для аренды NL;
- во вход поиска — обратная связь заказчика (`research_feedback_block`): одобренное, отклонённое
  с причинами, правила, источники, которым доверяет, уже найденное по теме.

**Модели радара — свои** (`SIGNAL_JUDGE_*`, `SIGNAL_REVIEW_*`, `SIGNAL_DEDUP_*`, `SIGNAL_RESEARCH_*`):
- `OPENAI_MODEL` ленты не трогается;
- лимит ответа растёт с уровнем рассуждения (`output_budget`);
- таймаут радара — 240 с;
- у gpt-5 своя цена.

**Экраны:**
- на карточке — «Событие: ДД.ММ.ГГГГ»; в раскрытой — разбивка балла «критерий · вес — балл»;
- у админа — «Скрытые (N)» с причиной и плитка «Скрыто»; API `hidden=true` — 403 не админу;
- «Скоринг» — плашка вкладки «Технологический радар» по факту подключения;
- «Статистика» — расход радара отдельно от ленты:
  - строки `radar_*` в `ai_processing_runs` (поиск, судья, ревью, дедуп; плата за вызовы
    web_search — `SIGNAL_WEB_SEARCH_USD_PER_CALL`);
  - столбец «ИИ-обработка» делится на ленту и радар;
  - «₽ за статью» — без радара.

**Хвосты ревью 29.09:**
- «ответ без текста» — временный сбой, с повтором;
- судья не ответил ни на один кластер — задача падает, а не «ok, 0»;
- лимит генерации запросов 600 → 1200.

## Сравнение (локально, 30.09–01.10)

Три темы, одни и те же 30 дней:

| | A: Brave + gpt-5-mini | C: Brave + судья gpt-5 | B: «режим ChatGPT» |
|---|---|---|---|
| На радаре | 3 (сильная одна) | 0 — судья счёл находки Brave бизнесом и мусором | 4, все — первоисточники |

Все 13 тем в режиме B:
- на радаре 28 технологических карточек, почти все — события сентября; шортлист — 4;
- много российских («Роснефть», «Газпром нефть», «Башнефть», ЛУКОЙЛ, НОВАТЭК);
- 29 бизнес-карточек сохранены, но скрыты; 7 смешанных — скрыты;
- 98 событий, 83 подтверждены;
- поиск — $2,44 за 291 поисковый вызов (с повторами); прогон ~2 ч.

## Ревью — на что смотреть

- `upsert_signal`: поля судьи — COALESCE (старая сборка NL их не стирает); балл и
  происхождение — всегда вместе.
- `_RADAR_VISIBLE_SQL` / `_RADAR_HIDDEN_SQL` / `_radar_hidden_reason_sql` — одни правила в трёх
  местах.
- `signal_research`: проверка ссылки, повтор, признак продвижения.
- `record_radar_ai_usage`: идемпотентность через DELETE по `job_id` (уникальный ключ с NULL
  `article_id` повтор не ловит).

Ревью — свежей сессией (`/code-review`), не автором.
