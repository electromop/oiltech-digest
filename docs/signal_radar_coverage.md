## Запуск

Гибкий поиск без привязки к локальным источникам:

```bash
python -m oiltech_digest.cli seed-signal-topics
python -m oiltech_digest.cli discover-signals --web-only --no-offline --max-signals 20 --limit 80 --web-query-limit 8
```

Быстрый offline smoke-test по одной теме:

```bash
python -m oiltech_digest.cli discover-signals --web-only --offline --topic "Бурение" --limit 12 --max-signals 3
```

Для нишевых тем вроде цементирования, петрофизики или лабораторных испытаний лучше использовать `--no-offline`, больший `--limit` и больший `--web-query-limit`: там один короткий поиск часто не набирает достаточно сильных evidence для offline-эвристики.

## Как строятся поисковые запросы

Для каждой темы радар берет три слоя:

- ОС администраторов: `signal_query_hint` и мягкие `site:`-предпочтения.
- `signal_radar_topics`: название, описание и `query_seeds_json`.
- Связанные теги из основного дерева `tags`: `name`, `name_en`, `description`, `keywords_json`, `keywords_en_json`.

Стоп-слова из `tags.negative_keywords_json` не добавляются в каждый поисковый запрос как жесткий `-term`. Они используются как пост-фильтр web evidence и как контекст `avoid meanings` для генератора запросов. Это снижает шум, но не ломает поиск полезных статей, где стоп-слово встречается в нейтральном сравнении.
